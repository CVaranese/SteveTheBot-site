Imitation with frame history

13 Nov 2026 · T-4 · Replays

Abstract

A network that sees only the current frame cannot tell what happened in the last half second, and a human's next input often depends on that. Giving past frames to a network trained by self-play had not helped, but imitation is where memory should matter most. This experiment trained two networks on all recorded human games with this character on both sides on this stage, with the same budget and seed: one sees the current frame only, the other adds three past frames. Both were judged on how well they predict the human's next input on games they never trained on. Frame history lowered the prediction error only slightly, from 0.620 to 0.612; the gap kept its sign at the half-way point but was well under the expected size. Both networks mostly repeat the last input: their accuracy, 0.840 and 0.841, is barely above that of always repeating it. On the frames where the human changes input both are right only 0.083 and 0.087 of the time, as a share of one. Stacked past frames therefore add little to imitation, and changes of input remain the hard part of copying human play.

Question and hypothesis

A network that sees only the current frame cannot tell what happened in the last half second, and a human's next input often depends on that. An earlier experiment found that giving past frames to a network trained by self-play did not help. Imitation is where memory should matter most, so this experiment trains two networks on the same human games, one with the current frame only and one with three past frames added, and compares how well each predicts the human's next input on games it has not seen.

Written in the experiment plan on 13 Nov 2026, before the runs:

Expected (guesses, written before): the twin's held-out cross-entropy lower by 0.02 to 0.10; accuracy on input changes higher by 0.02 to 0.06; overall accuracy within 0.01 of the plain run (the copy-the-queue shortcut dominates it).

T4ImFull itself: held-out accuracy 0.84 to 0.86, on changes 0.05 to 0.15 (more data than T4Im300's 254 games).

"The twin" is the network with frame history and "T4ImFull" the plain one. "Cross-entropy" is the prediction error (lower is better). "The copy-the-queue shortcut" is predicting that the human repeats their last input, which is right on most frames.

Discussion

Frame history lowered the prediction error by a small amount. The held-out cross-entropy at the end is 0.620 for the plain network and 0.612 with frame history (Table 2). The gap has the same sign at the half-way point (the "update 10000" lines). It is well under the lower bound of the first quote.

Both networks mostly repeat the last input. Their accuracy (0.840 and 0.841) is barely above the accuracy of repeating the last input (0.835 and 0.836).

Changes of input stay hard for both. On frames where the human changes input the networks are right 0.083 and 0.087 of the time, as a share of one. Frame history adds little there, less than the first quote expected.

The plain network's own scores are inside their expected ranges. The second quote's ranges for accuracy and for accuracy on changes both contain the plain run's final values.

Limitations

  • One run of each kind, one seed.
  • One network size and one kind of memory (stacked past frames). A larger network or a recurrent one was not tried.
  • Prediction scores on held-out games say how well a network copies, not how well it plays; play was compared in the next experiment.
  • Both runs were still improving slowly when they stopped.
  • The dataset is another project's collection of human games; it is used privately and is not redistributed.

Decision

Both networks were trained on with PPO (the human line, above) to compare in play.
