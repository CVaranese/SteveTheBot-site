Input variants

11 Nov 2026 · T-9 · Inputs

Abstract

The network sees the game as a list of numbers, most of which are two large one-hot blocks saying which animation each character is in. This experiment tries two changes to the input at the same training budget: replacing each animation block with a short list of learned numbers (an embedding), and telling the network which action it chose at its previous decision. Four self-play runs of equal length were trained, one per variant (plain inputs, the previous action, the embedding, and both together), and each played a frozen PPO model and the scripted bot at level 9. The two runs with the previous action scored highest against the frozen model: 72% for the previous action and 69% for both together, against 54% for plain inputs. The embedding alone scored lowest, against expectation: 32% against the frozen model and 42% against the scripted bot. With a single run per variant these differences are not established; a follow-up with a second seed did not confirm the gain of the previous action.

Question and hypothesis

The network sees the game as a list of numbers. Most of that list is two large one-hot blocks that say which animation each character is in. This experiment tries two changes to the input at the same training budget: replacing each animation block by a short list of learned numbers (an embedding), and telling the network which action it chose at its previous decision.

Written in the experiment plan on 11 Nov 2026, before the runs:

Baseline noise: T9Base and PPO8Self within about 10 wins of each other against the frozen model.

T9Emb: about equal to the baseline (an embedding is a factorised first layer; it mainly saves weights).

T9Prev: a small gain, 5 to 10 wins against the frozen model (the bot can keep a move going).

No variant loses more than 10 wins to the baseline.

In these quotes "T9Base" is the run with plain inputs, "T9Emb" the run with the embedding, "T9Prev" the run with the previous action, "PPO8Self" an earlier run with plain inputs and another seed, and "the frozen model" a saved copy of PPO8Self used as a fixed opponent. "Wins" are counted out of 100 games.

Discussion

The two runs with the previous action scored highest against the frozen model. Plain inputs won 54%; the previous action won 72% and the embedding with the previous action 69%. The third quote expected a smaller gain than Table 3 shows.

The embedding alone scored lowest, against the expectation. It won 32% against the frozen model and 42% against the scripted bot at level 9, both below plain inputs (54% and 71%). The second quote expected it about equal to plain inputs, and the fourth expected no variant to fall this far.

With one run per variant these differences are not established. A follow-up experiment repeated the variants with a second seed and did not confirm the gain of the previous action.

Limitations

  • One run per variant. The intervals in the tables cover chance between games only, not the difference between training runs.
  • The first quote compares the plain-input run with an earlier run (PPO8Self). That run is the frozen opponent of the first table, so the comparison is not shown on this page.
  • The embedding was tried with one starting spread of its table. Why it scored low was not tested here.
  • The frozen opponent and the scripted bot are this project's own; no variant was scored against the game's own computer player.
  • The scores were measured on the copy saved at the end of each run.

Decision

Checked with a second seed (T-12, above).
